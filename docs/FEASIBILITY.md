# تقييم الجدوى — إصدار أولي

## الهدف

التحقق من أن GitHub يستطيع تشغيل خط إنتاج مجدول بميزانية صفر، وأن الناتج يمكن إدارته من الهاتف دون تحويل GitHub إلى خادم دائم.

## البنية المقترحة للاختبار، وليست قرارًا نهائيًا

1. مستودع جديد يحوي الكود وسجل التطوير فقط.
2. GitHub Actions ينفذ مهامًا قصيرة عند الطلب أو بجدول زمني: جمع فكرة، إعداد مسودة، فحصها، توليد صوت، تركيب فيديو، حفظ تقرير.
3. نقطة موافقة بشرية قبل أول نشر. عند نجاح الاختبار، يضاف النشر الرسمي لصفحة Facebook بمفاتيح محفوظة في إعدادات GitHub السرية، لا في ملفات المشروع.
4. واجهة هاتف خفيفة لإدارة المحتوى والتقارير تضاف بعد حسم مكان التخزين الدائم.

## الرؤية والخصوصية

اختار المستخدم أن يكون المشروع كله عامًا، بما في ذلك الشفرة والخصائص وسجلات التشغيل. يجب ألا تدخل أسرار أو بيانات اعتماد في المستودع.

## اختيار النموذج الأولي

النموذج المبدئي هو `qwen2.5:1.5b-instruct`: حجمه المعلن 986 MB وترخيصه Apache 2.0، وصفحة النموذج تذكر دعم العربية. هذا اختيار للتجربة فقط؛ لم تُختبر جودة نصه العربي أو دقته العلمية. النموذج لا يغني عن التحقق من المصادر.

## ما يؤيده التوثيق حاليًا

- GitHub Actions يدعم التشغيل اليدوي والمجدول، لكن الجدولة قد تتأخر وقت الضغط، كما أن تشغيل المستودع العام يتوقف آليًا بعد 60 يومًا بلا نشاط.
- الحد الأدنى لدورية الجدولة الموثق هو مرة كل خمس دقائق؛ لذلك لا ينبغي الوعد بتوقيت دقيق بالدقيقة.
- عامل Linux القياسي للمستودع العام: 4 CPU و16 GB RAM و14 GB SSD. الاستخدام القياسي للمستودعات العامة مجاني حسب جدول GitHub الحالي. أما المستودع الخاص فيعتمد على حصة الخطة وقد تُحتسب رسوم عند تجاوزها.
- خطة GitHub Free الشخصية تتضمن حاليًا 2,000 دقيقة Actions شهريًا و500 MB artifacts و10 GB cache لكل مستودع. هذا يسمح بنموذج أولي خاص منخفض التشغيل، لا بتخزين مكتبة فيديوهات دائمة. يجب وضع سقف إنفاق صفر كي تتوقف المهام عند استنفاد المجاني.
- يعمل كل عامل GitHub-hosted في آلة افتراضية جديدة؛ فلا ينبغي الاعتماد على بقاء الملفات المحلية أو النموذج بين تشغيل وآخر.
- artifacts وسجلات GitHub Actions تحفظ افتراضيًا 90 يومًا، ويمكن حذفها قبل ذلك؛ لذلك هي وسيلة تسليم مؤقتة لا مخزن أرشيف.

## المخاطر التي سنختبرها قبل بناء المصنع

### النموذج المحلي داخل العامل

تنزيل نموذج بحجم يقارب 1–2 GB في كل تشغيل قد يستهلك وقتًا ومساحة ونقل بيانات. يمكن اختبار التخزين المؤقت للأوزان، لكن لا نعتمد عليه قبل تجربة فعلية. يجب اختيار ترخيص يسمح بالاستخدام التجاري قبل مسار تحقيق الدخل؛ حجم النموذج وحده لا يكفي للاختيار.

### البحث والتحقق العلمي

النموذج يولد نصوصًا ولا يثبت صحة الادعاءات. يجب أن يرافق كل ادعاء مصدر قابل للمراجعة، وأن تفشل مرحلة الاعتماد إذا غابت المصادر أو تعذر التحقق.

### الحالة وملفات الفيديو

المجلد المؤقت في العامل ليس مخزنًا دائمًا. لا توضع الفيديوهات أو قاعدة البيانات في تاريخ Git. نحتاج اختيارًا مجانيًا للتخزين الدائم مع حد واضح للسعة والاحتفاظ، أو بدء التجربة بتنزيل الناتج كـ artifact لفترة محدودة ثم تقييم ذلك.

### واجهة الهاتف

GitHub Pages وحده يستضيف ملفات ثابتة ولا يوفر قاعدة بيانات تطبيق. يجب اختبار أسهل مسار مجاني للإدخال ومراجعة النتائج قبل بناء لوحة مخصصة؛ قد تكون واجهة GitHub نفسها كافية لإثبات الفكرة الأولى.

### النشر والتحليلات

لن نطلب أسرار Meta قبل تحديد الصلاحيات المطلوبة وشرحها. يبدأ الاختبار بتجهيز ملف فيديو فقط؛ ولا ينشر النظام تلقائيًا حتى إتمام مراجعة الصلاحيات واختبار وضع المسودة. دعم جدولة Reels وجمع بيانات الأداء يجب التحقق منهما على إصدار Meta الفعّال قبل كتابة التكامل.

## معيار تجربة إثبات المفهوم

- Workflow يدوي واحد.
- تنزيل نموذج مرخص للاستخدام التجاري، وإنتاج مسودة عربية من فكرة ومصادر يعطينا المستخدم إياها.
- حفظ المسودة كـ artifact قصير الاحتفاظ؛ يحتفظ GitHub بالـ artifacts افتراضيًا 90 يومًا ولا يصلح أرشيفًا دائمًا للفيديو.
- لا اتصال بفيسبوك، ولا نشر، ولا تخزين مفاتيح.
- لا تبدأ مرحلة الفيديو قبل نجاح هذا الاختبار وتحديد طريقة حفظ الناتج.
